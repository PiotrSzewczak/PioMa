## Tytuł
[API] Koncepcja endpointu do dynamicznego wyszukiwania adresów / mieszkań (autocomplete)

## Cel
Zaprojektowanie koncepcji endpointu API do dynamicznego wyszukiwania adresów i mieszkań,
wywoływanego wielokrotnie w trakcie wpisywania tekstu przez użytkownika (autocomplete / live search).

Na tym etapie celem NIE jest implementacja, tylko:
- opis zachowania endpointu
- logika wyszukiwania
- sposób budowy zapytania SQL
- uwagi dotyczące wydajności

Endpoint będzie w przyszłości implementowany w Pythonie i oparty o relacyjną bazę danych SQL.

## Kontekst
System będzie udostępniał wyszukiwarkę adresów mieszkań (apartamentów).
Każdy rekord reprezentuje konkretne mieszkanie i posiada:
- identyfikator adresu
- identyfikator mieszkania
- pola adresowe (miasto, ulica, numer budynku, numer lokalu)

Frontend będzie wywoływał endpoint bardzo często (po każdej wpisanej literze lub po 2–3 znakach).

Przykład zachowania:
- użytkownik wpisuje: `Warszawa Łokietka`
- w bazie istnieje rekord: `Warszawa, ul. Władysława Łokietka 51, lok. 13`
- wynik powinien zostać zwrócony mimo braku pełnej frazy „Władysława”

Oznacza to, że fragment „Łokietka” musi zostać dopasowany do pełnej nazwy ulicy
„Władysława Łokietka” przy użyciu operatora typu `LIKE / ILIKE`.

## Zakres taska
- zaprojektowanie struktury endpointu (request / response)
- opis logiki dynamicznego wyszukiwania tekstowego
- obsługa niepełnych i skróconych fraz wpisywanych przez użytkownika
- wyszukiwanie case-insensitive
- wykorzystanie operatora `LIKE / ILIKE` z wildcardami (`%`) po obu stronach wartości
- uwagi dotyczące wydajności przy dużej liczbie zapytań

## Założenia techniczne
- Backend: Python
- Baza danych: SQL (docelowo PostgreSQL lub kompatybilna)
- Brak full-text search na tym etapie
- Brak zewnętrznych silników wyszukiwania (Elasticsearch, OpenSearch itp.)

## Logika wyszukiwania (koncepcja)
- Wprowadzona fraza jest dzielona na tokeny (np. po spacjach)
- Każdy token jest używany w zapytaniu SQL w postaci:
  `ILIKE '%token%'`
- Warunki dla tokenów są łączone operatorem `AND`
- Tokeny są dopasowywane do wielu kolumn adresowych (miasto, ulica, numer budynku, lokal)
- Przykładowo:
  - input: `Warszawa Łokietka`
  - zapytanie powinno dopasować rekord:
    `Warszawa, Władysława Łokietka 51, 13`

## Oczekiwane zachowanie
- Wyszukiwanie działa dla niepełnych nazw ulic i adresów
- Wielkość liter nie ma znaczenia
- Dopasowanie działa również wtedy, gdy użytkownik pominie część pełnej nazwy
- Endpoint nadaje się do użycia jako autocomplete (krótkie czasy odpowiedzi)

## Kryteria akceptacji (koncepcyjne)
- Opisana logika umożliwia dynamiczne wyszukiwanie adresów
- Jasno określony sposób budowy zapytania SQL
- Uwzględnione potencjalne problemy wydajnościowe
- Endpoint nadaje się do wielokrotnego wywoływania w krótkim czasie
